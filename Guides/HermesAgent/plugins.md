# Плагины для Hermes Agent

Официальные источники: [Build a Hermes Plugin](https://hermes-agent.nousresearch.com/docs/developer-guide/plugins), [Plugins](https://hermes-agent.nousresearch.com/docs/user-guide/features/plugins).

## Сначала выбери правильную поверхность

Нативный плагин подходит для новых инструментов, хуков, slash-команд, навыков и расширений CLI. Для MCP-сервера, TTS, event hook, десктопного расширения или другого backend Hermes может предусматривать отдельный формат. Сверься с картой интерфейсов в официальном руководстве до выбора структуры.

Hermes поддерживает несколько видов плагинов, в частности нативный Python-плагин и совместимые Portable Agent Plugins v1 пакеты. Не смешивай их файлы-манифесты и правила регистрации.

## Нативный плагин

Создавай отдельный каталог в `Plugins/HermesAgent/<имя>/` с `plugin.yaml`, Python entry point с `register(ctx)` и только необходимыми модулями и данными. Декларируй зависимости и запрашивай только нужные capabilities. Для секретов используй предусмотренную Hermes конфигурацию окружения, не храни значения секретов в репозитории.

Опиши инструменты так, чтобы их имя, схема, описание и ошибки были ясны модели и пользователю. Для опасных или изменяющих состояние действий учитывай consent-механику Hermes и корректно обрабатывай отсутствие разрешения. Плагин должен корректно работать при повторной загрузке в предусмотренном жизненном цикле и не выполнять побочные действия при импорте модуля.

Если плагин поставляется вместе с навыком, приложи его к плагину согласно официальному API регистрации навыков; не рассчитывай, что отдельная папка `Skills/` автоматически включится в пакет.

## Portable Agent Plugins v1

Для переносимого пакета используй его собственную структуру, например `plugin.json`, `skills/<name>/SKILL.md` и при необходимости `mcp.json`. Добавляй только поддерживаемые компоненты и валидные декларации. Не помещай секреты в `mcp.json` или другие открытые файлы пакета.

## Проверка и установка

Перед выпуском используй доступные для установленной версии проверки:

```bash
hermes plugins doctor ./Plugins/HermesAgent/<имя>
hermes plugins validate ./Plugins/HermesAgent/<имя>
```

Флаги валидатора могут различаться по версии; смотри `hermes plugins validate --help`. Проверь регистрацию инструментов и навыков в изолированной среде, работу без необязательных секретов и поведение при отказе в capability.

Для локальной проверки пользовательский плагин устанавливают в `~/.hermes/plugins/<имя>/`, затем включают командой `hermes plugins enable <имя>`. Для установки и обновлений из Git используй `hermes plugins install <владелец>/<репозиторий>`; при воспроизводимом развёртывании фиксируй полную SHA коммита. До запуска проверь исходный код, запрашиваемые разрешения и зависимости. Проектные `.hermes/plugins/` не считай универсальным способом загрузки: gateway-сессии их не обнаруживают.
